# 世界生成算法设计（Project Sandbox）

> 状态：设计草案，待批准后分阶段实施（每阶段 ≤2 文件）
> 对齐基线：WorldGenerator.cs（S1 分层填充版）、blocks.json（5 块）、world_gen.json（v1 四字段）、存档格式 v1（冻结，不改）

---

## 1. 目标与范围

把世界生成从「平面分层填充」升级为六模块管线：**Perlin 噪声（地形高度场）→ Voronoi（群系分区）→ 群系边界混合 → 细胞自动机（洞穴）→ 矿脉（噪声阈值 + 团簇游走）→ 逐格组装**。

硬约束（沿用项目红线）：
- 纯 C# 实现，无第三方库；Perlin/Voronoi/CA 全部原创手写（公开教科书算法，非复制任何游戏代码）
- 世界完全由 seed 重放，**不落盘世界区块** → 存档格式 v1 零改动，天然兼容
- 原创词根命名（与 items.json 词根对齐），无泰拉瑞亚痕迹
- v1 旧分层模式保留为 fallback（现测试断言零破坏）

## 3. 总管线架构

```
                    seed（world_gen.json 或调用方传入）
                              │
        ┌─────────────────────┼──────────────────────┐
        ▼                     ▼                      ▼
  ①HeightMap           ②BiomeVoronoi          ③CaveMask(CA)
  Perlin 分形 1D 采样    撒点+温度/湿度双轴      石层带内 4-5 规则
  → float[width] 地表高   → 每格群系归属          → bool 洞穴掩码
        │                     │                      │
        └──────────┬────── ④BiomeBlend 边界过渡 ─────┤
                   ▼                     ▼            ▼
              ⑤OreVeins          ⑥Compose 逐格组装（优先级判定）
  噪声阈值+锚点游走团簇  →  BlockGrid（ushort 索引网格）
```

**⑥ Compose 逐格优先级（高 → 低）**：

```
1. y < heightMap[x]             → 空气（空块）
2. caveMask[x,y] == 洞穴        → 空气（挖出的空腔）
3. oreMark[x,y] 命中            → 对应矿块
4. y == heightMap[x]            → 群系表层块（经边界混合）
5. y ∈ (地表, 玄武岩顶)          → 群系下层块（页岩等）
6. y ≥ 玄武岩顶                 → tile_basalt_firm（不可挖底盘，游戏边界）
```

全部六模块同签名的接口：`IWorldGenStage`（可选引入，阶段 2 再定，当前用私有方法编排即可）。

## 4. 分块算法设计

### 4.1 Perlin 噪声：地形高度场

**职责**：产出 `float[] heightMap`（每列地表高度），替代平面分层的地表。

**实现**（原创手写经典梯度噪声）：
- 基类 `PerlinNoise(seed)`：512 长度置换表由 seed 派生 RNG 洗牌（`RandomNumberGenerator.Seed = seed`）
- `Noise2D(x, y)`：晶格梯度点乘 → fade 曲线 `6t⁵-15t⁴+10t³` → 双线性混合，值域 [-1, 1]
- `Fractal(x, octaves, persistence, lacunarity)`：多倍频叠加归一化

**参数**（world_gen.json `terrain` 段，§6）：

```json
"terrain": {
  "octaves": 4, "persistence": 0.5, "lacunarity": 2.0,
  "base_height": 18, "height_amp": 6,
  "sample_freq": 0.05
}
```

**高度公式**：`heightMap[x] = clamp(base_height + amp * Fractal(x * sample_freq), air_rows + 1, basalt_top - 2)`。钳制保证空中可呼吸带与玄武岩底盘永远存在（玩家出生与游戏边界安全）。

### 4.2 Voronoi 群系分区

**职责**：把世界划成若干 Voronoi 单元，每单元一个群系；群系由（温度, 湿度）双轴参数映射到原创词根群系。

**实现**（暴力最近邻，小世界无压力；预留 JFA 跳点优化注释）：
- seed 派生 RNG 在世界范围撒 `cell_count` 个单元点
- 每单元按 `biome_weights` 权重随机取一个群系
- 逐格 `argmin` 欧氏距离指派归属 → `BiomeId[,] biomeMap`

**群系表**（6 个原创，全部对齐 items.json 现词根）：

| 群系 | 温度/湿度 | 表层块 | 下层块 | 特征 |
|---|---|---|---|---|
| 苔光林 | 温/润 | tile_soil_loam | tile_stone_shale | 撒苔灯（tile_moss_lantern，非 solid 装饰）+ 伐木块（tile_bough_timber） |
| 余烬荒 | 热/干 | tile_soil_ember（新） | tile_stone_shale | 灰烬色调表层 |
| 霜纹台地 | 冷/湿 | tile_soil_rime（新） | tile_stone_shale | 霜色表层 |
| 页岩坡 | 中/干 | tile_stone_shale | tile_stone_shale | 裸岩坡 |
| 晶簇洞 | 无关（洞穴带覆盖） | tile_stone_shale | tile_stone_shale | 洞穴内生成晶簇矿的概率提升 |
| 潮汐滩 | 湿/中 | tile_soil_tide（新） | tile_stone_shale | 水域未实现，先做块着色 |

### 4.3 群系边界混合

**职责**：消除 Voronoi 硬拼缝。

**实现**：对边界带（到 Voronoi 边距离 ≤ `blend_width` 的格）计算边界距离场 d ∈ [0,1]，表层块按 `d` 在两个相邻群系的表层块间二选一（sigmoid 阈值 `1/(1+e^(-k(d-0.5)))`）。规则表 `biome_blend` 存 world_gen.json（如 loam↔rime 允许混合；loam↔basalt 底盘不混合——底盘不进混合）。

### 4.4 细胞自动机洞穴

**职责**：在石层带内生成自然洞穴空腔。

**实现**（4-5 规则经典 CA）：
- 初始化：带 `y ∈ [max(heightMap)+2, basalt_top-2]` 内每格以 `density` 概率标为「墙」，其余「空」
- 迭代 `iterations` 轮（经典 4-5：出生 5 / 存活 4）：「空」格八邻（含四角）墙计数 ≥ `wall_threshold` 则成墙；已为「墙」的格子八邻墙计数 ≥ `wall_threshold-1` 则存活，否则转为空
- 清扫：BFS 连通分量 < `min_room` 的孤立空腔填回墙（避免碎噪点洞）

**参数**：

```json
"caves": { "density": 0.45, "iterations": 4, "wall_threshold": 5, "min_room": 8 }
```

**保证**：洞穴只在石层带内，不破坏地表/底盘 → 玩家行走面与游戏边界完好；洞穴与地表连通性不作强制（封闭溶洞也合法，玩家可挖到）。

### 4.5 矿脉

**职责**：两类矿脉生成——噪声阈值条带 + 锚点游走团簇，产出长条状矿簇。

**实现**（双通道）：
1. **阈值矿脉**：独立子种子 Fractal 噪声，`Noise2D(x*0.12, y*0.12) > 0.62` 且 y 在 `depth_band` 内 → 标矿
2. **游走团簇**：每列以 `anchor_per_col` 概率撒锚点，随机游走 `walk_steps ∈ [min,max]` 步，每落点画 `cluster`×`cluster` 团簇（同矿型），形成「长条感」

**矿脉表**（矿石块全部新增，掉落物全部已存在于 items.json）：

```json
"veins": [
  { "ore": "tile_ore_iron",   "depth_band": [14, 20], "anchor_per_col": 0.05, "walk_steps": [20, 40], "cluster": 3 },
  { "ore": "tile_ore_crystal","depth_band": [18, 26], "anchor_per_col": 0.04, "walk_steps": [24, 44], "cluster": 2 },
  { "ore": "tile_ore_amber",  "depth_band": [16, 24], "anchor_per_col": 0.03, "walk_steps": [20, 36], "cluster": 2 },
  { "ore": "tile_ore_ember",  "depth_band": [20, 28], "anchor_per_col": 0.04, "walk_steps": [16, 32], "cluster": 3 }
]
```

**掉落衔接**：矿块硬度 3~4，挖掉后由 LootSystem 按 `loot.json`（未创建，属另一任务）配置掉落 `item_iron_pellet` / `item_crystal_shell` / `item_amber_glob` / `item_fire_vein`。本设计只声明接口依赖，不越权实现掉落。

### 4.6 组装 Compose

按 §3 优先级逐格写入 BlockGrid。`heightMap`、`biomeMap`、`caveMask`、`oreMark` 四张中间图的存取全部在生成期内，不落盘、不进存档。

## 5. 确定性方案（seed 链）

```
seed（world_gen.json "seed" 字段；0 = 时间派生，非 0 = 确定性）
  ├─ PerlinNoise(seed ^ 0x9E3779B9)          → 高度场
  ├─ VoronoiRNG(seed ^ 0x85EBCA6B)           → 群系
  ├─ CaveRNG(seed ^ 0xC2B2AE3D)              → 洞穴
  └─ OreRNG(seed ^ 0x27D4EB2F)               → 矿脉（黄金比例散列常量）
```

- 同一 seed → 逐格相同世界（确定性回归可断言）
- 世界不落盘：存档 Header.Seed 已有字段，未来 Game.cs 把真实 seed 写入（**格式不变，纯填值**）
- Game.cs 调用点：`generator.Generate(seed)`，seed 从 world_gen.json 读取；与存档接线留阶段 4

## 9. 性能预算

- 64×48 = 3,072 格：CA 4 轮 × 8 邻 ≈ 10 万次比较；Voronoi 3,072 × 8 点 ≈ 2.5 万次距离 → **总预算 <5ms，无压力**
- 未来 512×256 = 13.1 万格：Voronoi 暴力会到百毫秒级 → 预留 JFA 跳点算法接口注释（阶段 2 只留注释不实现）
- 全部中间图在生成期 GC 回收，无常驻内存

1. **出生点埋土**：地形波动后 Game.cs 硬编码 y=11 失效 → 阶段 4 加「从 heightMap 查地表」逻辑，读档加地面夹紧

3. **存档兼容**：世界重放不落盘 → v1 兼容天然成立；唯一隐患是读档时旧位置在新地形里悬空/埋土（同上 1）

6. **原创合规**：群系名/块名全部来自项目已有词根，无第三方噪声库、无任何游戏逆向内容
