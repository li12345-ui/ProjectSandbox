### 1.3 三级索引：元数据（Metadata）

每条索引记录必须携带以下元数据字段（在 AI 上下文窗口中作为检索上下文前缀）：

```
[领域::类型] 文件名 (@路径) [状态] [里程碑] [依赖] [关键词]
```

字段说明：

| 字段 | 必填 | 格式 | 示例 |
|---|---|---|---|
| 领域 | 是 | 领域代码 | `CORE` |
| 类型 | 是 | 类型代码 | `INTERFACE` |
| 文件名 | 是 | basename | `IEventBus.cs` |
| 路径 | 是 | 仓库相对路径 | `src/Core/IEventBus.cs` |
| 状态 | 是 | `draft` / `stable` / `frozen` / `deprecated` | `stable` |
| 里程碑 | 是 | `M0` / `M1` / `M2` / `M3` / `M4` | `M0` |
| 依赖 | 否 | 逗号分隔的路径列表 | `src/Core/IEventBus.cs` |
| 关键词 | 是 | 空格分隔的检索词 | `事件 总线 订阅 发布 解耦` |

## 二、检索规则

### 2.1 关键词检索（Keyword Search）

**规则 K1：三级关键词匹配**
- 检索词命中「文件名」「关键词」「领域名/类型名」任意一项即返回
- 中文/英文同义词视为等价（如 "EventBus" = "事件总线"）
- 支持前缀匹配（如 `item` 命中 `item.schema.json` 和 `items.json`）

**规则 K2：状态过滤**
- 默认排除 `deprecated`
- 变更影响分析时仅看 `stable` 和 `frozen`
- 规划新功能时可看 `draft`

**规则 K3：里程碑过滤**
- 当前开发里程碑为 `M0`，检索默认限定 `M0` 资产
- 跨里程碑检索需显式声明（如 "查找 M1 需要的 World 层接口"）

### 2.2 依赖链检索（Dependency Chain）

**规则 D1：前向依赖（谁依赖我）**
- 输入：一个文件路径
- 输出：所有在「依赖」字段中引用该路径的索引记录
- 示例：查 `src/Core/IEventBus.cs` → 返回 `MemoryEventBus.cs`、`CoreSelfTest.cs`

**规则 D2：后向依赖（我依赖谁）**
- 输入：一个文件路径
- 输出：该文件「依赖」字段中列出的所有索引记录
- 示例：查 `Main.cs` → 返回 `src/Core/*` 全部 6 个文件

**规则 D3：递归闭合**
- 变更一个 `stable` 文件时，必须递归查出所有前向依赖，形成「影响面清单」
- 影响面清单长度 > 5 时，触发「拆分提交」建议（编码规范 R1：一次 ≤2 文件）

### 2.3 变更影响面检索（Impact Analysis）

**规则 I1：接口变更广播**
- 任何 `INTERFACE` 类型文件的修改，自动广播到所有 `IMPL` 和 `TEST` 类型前向依赖
- 必须校验：实现类是否仍满足接口契约

**规则 I2：Schema 变更级联**
- `SCHEMA` 类型文件修改 → 级联检查所有 `DATASET` 类型前向依赖
- 必须校验：数据集是否仍通过 schema 校验（如 items.json 对 item.schema.json）

**规则 I3：规范变更扩散**
- `SPEC` 类型文件修改 → 扩散到所有 `IMPL` / `TEST` / `DATASET`
- 示例：若「命名规范」新增一条规则，需扫描全部 C# 与 JSON 资产

**规则 I4：ADR 变更冻结**
- `ADR` 类型文件为 `frozen` 状态，修改即触发「新开 ADR」建议
- 不允许静默覆盖 ADR

### 2.4 按里程碑检索（Milestone Gate）

**规则 M1：里程碑边界**
- 每个里程碑交付前，必须检索该里程碑的全部 `stable`/`frozen` 资产，形成「交付清单」
- 交付清单必须与 GDD 对应章节逐项核对

**规则 M2：跨里程碑引用**
- `M0` 资产可被 `M1` 引用（向下兼容）
- `M1` 资产不可被 `M0` 引用（禁止向上引用未完成的接口）

### 2.5 快速定位速查表（Cheat Sheet）

| 我想找…… | 检索策略 |
|---|---|
| 某个接口的定义 | 领域=CORE + 类型=INTERFACE + 关键词 |
| 某个接口的实现 | 领域=CORE + 类型=IMPL + 依赖包含该接口路径 |
| 某个数据表的 schema | 领域=DATA + 类型=SCHEMA + 文件名匹配 |
| 数据表是否合规 | 领域=DATA + 类型=DATASET + 后向依赖到对应 SCHEMA |
| 修改一个文件会影响谁 | 前向依赖递归闭合（规则 D3） |
| 当前 M0 还差什么 | 领域=* + 里程碑=M0 + 状态≠stable/frozen |
| 规范怎么规定的 | 领域=SPEC + 关键词 |
| CI 怎么跑的 | 领域=CI + 类型=CONFIG |

## 三、维护与更新

### 3.1 索引更新触发条件

1. **新增文件**：文件落盘后立即追加索引记录，状态初始为 `draft`
2. **文件修改**：修改后若通过测试，状态可升 `stable`；若破坏契约，状态降 `draft`
3. **文件删除**：索引记录标记 `deprecated`，保留 1 个里程碑后移除
4. **里程碑切换**：批量扫描该里程碑全部资产，更新状态并生成交付清单

### 3.2 AI 协作时的索引使用协议

1. **每次任务开始前**：AI 先声明「本次任务涉及的领域+类型」，并检索相关索引记录
2. **每次任务完成后**：AI 更新受影响的索引记录（状态、依赖、关键词）
3. **不确定时**：AI 优先检索索引，禁止幻觉接口或臆造文件路径
4. **跨文件变更**：AI 使用「影响面清单」判断是否超出 ≤2 文件限制
