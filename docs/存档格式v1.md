# Project Sandbox — 存档格式 v1 设计（Save Schema v1）

**裁定**：本任务正是约束 4 允许的"明确授权时刻"——v1 定稿即冻结，此后任何字段变更必须升版本 + 走迁移接口，禁止原地改语义。格式 JSON 明文（System.Text.Json 属 .NET 内置，非第三方库），唯一读写口在 `src/Save/`，其他层禁止接触。

## 1. 总体结构

```json
{
  "format_version": 1,
  "header": { },
  "player": { },
  "world": { },
  "items": { },
  "npc": { },
  "progress": { },
  "migration": { }
}
```

## 2. 版本号与头部

```json
{
  "format_version": 1,
  "header": {
    "game_id": "project_sandbox",
    "save_id": "a1b2c3d4e5f6",
    "seed": 20261002,
    "created_at_utc": 1789900000,
    "updated_at_utc": 1789903600,
    "play_time_seconds": 3600
  }
}
```

- `format_version`：整数，加载第一道门禁；与构建版本无关，只在结构变更时 +1
- `save_id`：本存档唯一标识，防误加载他人文件
- save_id 与 seed 不得手改；改 seed 视为生成新世界而非读档

## 3. player（玩家）

```json
"player": {
  "pos": [230.5, 540.0],
  "hp": 80, "max_hp": 100,
  "mp": 0, "max_mp": 20,
  "coins": 25,
  "hotbar_size": 10,
  "inventory": [
    { "slot": 0, "item_id": "item_wood_log", "count": 40 },
    { "slot": 1, "item_id": "item_wood_pickaxe", "count": 1 }
  ],
  "equipment": {
    "main_hand": "item_wood_pickaxe",
    "off_hand": null,
    "armor": [null, null, null]
  },
  "unlocked_recipes": ["recipe_wood_pickaxe"]
}
```

- 背包按 slot 存储；空 slot 不落盘；装备引用 `item_id`（物品本体在 data/，存档只存引用+耐久例外）
- 有耐久物品需存 `durability` 余量（另字段），无耐久物品不存

## 4. world（世界）

```json
"world": {
  "name": "苔径林一号",
  "size": { "width_tiles": 4200, "height_tiles": 1200 },
  "time_of_day": 0.42,
  "day_count": 3,
  "chunks": [
    {
      "cx": 0, "cy": 0,
      "blocks": "base64(deflate 后的一维 block_id 字节流)",
      "walls": "base64(同上，背景墙层)"
    }
  ],
  "world_flags": { "bloom_opened": false }
}
```

- **chunk 分块落盘**（64×64 默认），只存与初始生成不一致的脏 chunk；未修改 chunk 由种子重算——避免全图落盘膨胀
- 物块 id 用 data/ 中 `tile_` 表；压缩用 .NET 内置 Deflate，禁第三方压缩库
- `world_flags`：世界级旗标桶，命名 `类别_词根`，入库过黑名单

## 5. items（世界中物品实体）

```json
"items": {
  "drops": [
    { "id": 7, "item_id": "item_coal", "count": 3, "pos": [410.0, 300.0], "expires_in_seconds": 240 }
  ],
  "chests": [
    { "pos": [1200, 600], "slots": [{ "slot": 0, "item_id": "item_copper_ore", "count": 12 }] }
  ]
}
```

- `drops`：地面掉落实体，含消失计时；`chests`：容器内槽位
- 玩家背包不在此节（见 player）

## 6. npc（前瞻预留，GDD v1.1 前冻结为空）

```json
"npc": {
  "gated": true,
  "entries": []
}
```

- NPC 定居系统是 GDD v1.0 非目标；字段先占位，`gated: true` 表示消费方（含迁移）不得读取 entries
- GDD v1.1 启用后按 draft_npc.schema.json 填充；占位期任何写操作直接跳过 NPC 节（**跳过不丢弃**，防未来数据丢失）

## 7. progress（进度）

```json
"progress": {
  "bosses_defeated": ["boss_shell_guard"],
  "events_cleared": ["event_stone_rain"],
  "milestones": ["milestone_first_night"],
  "unlocked_stations": ["workbench"]
}
```

- 只记"达成事实 + 达成时间戳（可选加 `at_utc`）"，不记过程态；可重放推导的数字一律不存
- `milestones` 用于任务/引导断点续接（quest 前瞻同 NPC，先留空数组）

## 8. migration（迁移接口）

```json
"migration": {
  "migrated_from": null,
  "applied": []
}
```

**协议（硬规则写死在 Save 层）**：

1. 加载流程：读 `format_version` → 若 `< 当前版本`，依序执行 `v(n) → v(n+1)` 的纯函数迁移
2. 每个迁移函数：输入旧结构 JsonNode → 输出新结构 + 在 `applied` 记录版本号，禁止迁移函数有副读存档文件以外的状态
3. **先行备份**：迁移开始前原文件复制为 `.bak`；任何一步失败 → 回滚并报错，禁止半迁移覆盖
4. `migrated_from`：首次读取旧版本时记录来源版本，供审计
5. 填默认值只允许填"新字段"，禁止借迁移改旧字段语义（语义变更 = 升版本 + 显式迁移而非静默重写）
6. 迁移清单驻留 `src/Save/Migrations/`，由代码表驱动，**不接受 data/ JSON 提供的迁移脚本**（防软内容越过代码层改存档）

## 9. 冻结与底线

- 存档格式 v1 定稿 = 冻结：改字段即升 v2 并附加迁移；评审必须过"存档格式变更"专项
- 网络协议事务不在此表，两轨独立评审
