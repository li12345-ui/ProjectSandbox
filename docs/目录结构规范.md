# Project Sandbox — 项目目录结构规范（v1.0）

> 依据：GDD v0.1（S1–S10）、ADR-001、合规清单 v1.0
> 原则：**代码管规则，数据管内容**；结构控制在 M1 需要的最小子集，不为未发生的需求预建设层级。

## 一、目录树（M1 最小子集）

```
ProjectSandbox/
├── project.godot            # 引擎配置唯一真源
├── ProjectSandbox.csproj    # 编辑器生成，禁手改
├── ProjectSandbox.sln       # 编辑器生成，禁手改
├── Main.tscn / Main.cs      # 启动入口（M0 后可迁至 scenes/）
├── assets/                  # 原创资产（入库单必填）
│   ├── art/                 # 精灵图/图集（Tileset、角色、UI）
│   ├── audio/               # 音乐/音效
│   └── fonts/               # 字体
├── data/                    # 软内容：只读 JSON（配方、物品、命名、掉落、词黑名单）
├── docs/                    # GDD、ADR、合规清单、本规范
├── scenes/                  # .tscn 场景文件，只做组装不放逻辑
├── src/                     # C# 源码，命名空间 = 目录点分路径
│   ├── Core/                # 基础服务：状态、资源加载、数据读取、事件接口
│   ├── World/               # S1 世界生成 / S2 挖掘物块
│   ├── Entities/            # 玩家（Player）、敌怪（Enemy）
│   ├── Systems/             # S3 合成 / S5 战斗 / S6 生存 / S7 首领 / S8 经济
│   ├── UI/                  # HUD、背包、合成面板
│   └── Save/                # 存档读写唯一入口（格式 v1 冻结）
└── tests/                   # 最小自测脚本（禁用第三方测试框架）
```

## 二、目录职责

| 目录 | 职责 | 硬规则 |
|---|---|---|
| assets/ | 全部美术/音频/字体，原创或授权 | 每个文件入库前填资产入库单 + 黑名单扫描 |
| data/ | 软内容 JSON：物品、配方、掉率、命名、文案 | **只读**：运行时加载后禁止写回；改内容改数据不改代码 |
| docs/ | 设计/架构/合规文档 | 文档变更与代码变更分开提交 |
| scenes/ | .tscn 节点组装与引用注入 | 场景文件内禁止内嵌数值表；业务数值一律走 data/ |
| src/Core/ | 规则地基：服务定位、资源/数据读取、事件接口定义 | 不依赖 World/Entities/UI 任何具体类型 |
| src/World/ | S1/S2：生成、物块网格、挖掘放置 | 不引用 Entities 具体类，经接口/信号交互 |
| src/Entities/ | 角色与敌怪 | 不直接引用 UI 与 data 文件名 |
| src/Systems/ | S3/S5–S8 游戏系统 | 系统间只经 Core 接口通信 |
| src/UI/ | HUD 与面板 | 只读状态、发指令，禁止直接改世界状态 |
| src/Save/ | 存档唯一读写口 | 格式 v1 冻结；其余层禁止直接访问存档 API |
| tests/ | 无第三方框架的最小脚本 | 任何层禁止引用 tests/ |

## 三、命名规则

**C#（与合规清单 ID 规则 `类别_词根` 保持一致，防两套体系冲突）**

| 对象 | 规则 | 示例 |
|---|---|---|
| 类/文件 | PascalCase，文件与主类同名 | `CraftingService.cs` |
| 命名空间 | `ProjectSandbox.<目录点分>` | `ProjectSandbox.Systems` |
| 节点 partial 类 | 场景名 + 关联脚本同名 | `Player.tscn` ↔ `Player.cs` |
| 私有字段 | `_camelCase` | `_hp`（避开引擎内置名） |

**资源/数据**

| 对象 | 规则 | 示例 |
|---|---|---|
| 场景/资源文件 | snake_case | `main_menu.tscn` |
| data JSON | snake_case 文件名与键 | `recipes.json`、`item_id` |
| 资产文件 | `类别_词根` snake_case | `mat_crystal_shell.png` |
| 物品/首领 ID | `类别_词根`，入库走黑名单 | `boss_shell_guard` |

硬性禁止：命名中出现任何对标作品的名称、同义直译、谐音缩写（见合规清单黑名单），违者废弃换词根，不做微调。

## 四、禁止跨层引用（可执行清单）

1. `data/` 不得引用 src/ 任何类；只被 Core 加载层读取
2. `scenes/` 不得硬编码数值、掉率、文本（一律数据驱动）
3. `World/` 禁止 `GetNode<Player>` 式直取实体——经 Core 事件接口交互
4. `Entities/` 禁止引用 `UI/`；状态上抛走接口，展示由 UI 订阅
5. `UI/` 禁止直接修改物块/世界状态，只允许调 Systems 指令接口
6. 各 System 间禁止互引具体类，只经 Core 服务接口
7. 全局事件总线为**既定冻结设施**：本规范只约定经 Core 定义的事件接口订阅，不得在任一层绕过 Core 私建总线副本
8. Core 不得反向依赖外层目录
9. 存档仅由 Save/ 接触；存档格式（v1）在本规范中冻结引用
10. 生产代码禁止引用 tests/；tests/ 可引用一切源码

## 五、与 GDD 映射

- S1/S2 → World
- S3/S5–S8 → Systems
- S9 → Save
- S10 → UI
- S4 建造拆分：物块操作在 World，家具配方在 data/，机关电路后续并入 Systems

无遗漏、无多余目录。
