# Project Sandbox — C#/GML 编码规范（v1.0）

**适用范围裁定**：ADR-001 已定 **Godot 4 + C# 单一主栈**。GML（GameMaker 语言）不在开发范围内，本条仅作备份条款，投入度为零；若未来触发"切 GML"需先重开 ADR-001。

## 一、命名规范（C# 主栈，硬性）

| 对象 | 规则 | 示例 | 备注 |
|---|---|---|---|
| 类/结构/枚举 | PascalCase | `CraftingService` | 与目录规范一致 |
| 方法/属性 | PascalCase | `GetRecipe()` | |
| 私有字段 | `_camelCase` | `_hp` | 避用引擎属性名（如 `_position` 留给引擎用途不回写） |
| 常量 | PascalCase | `MaxStackSize` | |
| 接口 | `I` 前缀 | `IEventSource` | |
| 节点 partial 类 | 与场景同名 | `Player.cs` ↔ `Player.tscn` | |
| 命名空间 | `ProjectSandbox.<目录点分>` | `ProjectSandbox.Systems` | |
| 物品/首领 ID | `类别_词根` snake_case | `boss_shell_guard` | 入库前走黑名单扫描（合规清单） |

**文件夹/资源/数据**：场景与资源 snake_case，data JSON 键 snake_case，资产 `类别_词根`（沿用目录规范第三节，不重复另立体系）。

## 二、文件组织

1. 一文件一主类；允许同类小私有类型同居一文件，禁止无关类堆叠
2. 业务逻辑不写进场景节点类——场景类只做节点接线，逻辑进 Systems/World（对应目录规范）
3. `using` 排序：System 系 → Godot 系 → 项目命名空间，禁含未用 using
4. 注释中文，XML doc 只写给对外主类型；注释解释"为什么"不重复"是什么"
5. 硬规则在代码、软内容在 data：禁止把掉率/配方/文本硬编码进 C#

## 三、提交信息

- 格式：`类型(范围): 中文主体`，类型限七大：`feat fix docs chore refactor test style`
- 示例：`feat(World): 新增岩层矿脉生成模板`
- 每提交对应一次交付且 **≤2 文件**；文档与代码分开提交；禁止混入无关改动；改动前先列文件清单

## 四、测试要求

1. **禁止第三方测试框架**（约束 3）；测试只在 `tests/`，用引擎最小脚本驱动
2. 每次交付必须附带：测试（静态可用性 + 动态步骤）+ 风险说明 + 验收标准（逐条可勾选）
3. 纯逻辑类（配方查找、数值计算）在 `tests/` 配最小自测脚本；场景/输入类只做手工验证步骤
4. 测试通过 ≠ 完成：验收标准逐条核对后才算交付

## 五、AI 修改限制（硬约束，每次任务必须遵守）

| # | 限制 | 出处 |
|---|---|---|
| R1 | 一次最多修改 2 个文件 | 约束 2 |
| R2 | 禁改存档格式、网络协议、全局事件总线（经 Core 订阅接口除外） | 约束 4 |
| R3 | 禁新增第三方库 | 约束 3 |
| R4 | 输出必含：补丁/文件 + 测试 + 风险 + 验收标准 | 约束 5 |
| R5 | 不确定先提问，禁止幻觉接口（先查官方文档/已有代码再动笔） | 约束 6 |
| R6 | 只做当前任务，不扩权 | 约束 1 |
| R7 | 全部命名/数值/文本原创，交付自带合规复核 | 约束 7 |

## 六、GML 备份条款（本栈不启用）

仅当 ADR-001 被重开且改判 GML 时才生效：命名沿用本规范（GML 脚本名 snake_case）、不做动态类型宽写（数据先声明结构）、提交/测试/AI 限制五节全文照用。在此之前，任何 GML 产出视为超范围。
