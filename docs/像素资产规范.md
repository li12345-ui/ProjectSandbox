# Project Sandbox — 原创像素资产规范（v1.0）

> 适用范围：assets/ 下全部美术（art）、音频（audio）资产的创作与入库
> 关联文档：目录结构规范（assets/ 职责）、GDD v0.1（2D 侧视像素沙盒）、合规清单 v1.0
> 硬红线：任何资产的尺寸/配色/帧率/命名不得引用对标作品独有数值与标志性组合；美术须逐帧原创绘制，禁止抓取、描摹、缩放镜像他人成品。

## 一、尺寸规范（单位为像素 px）

### 1.1 基础单位（Tile Grid）

| 用途 | 尺寸 | 说明 |
|---|---|---|
| 世界物块（Tile） | **16×16** | 全游戏最小网格单位，2D 侧视沙盒行业通用基线 |
| 物块图集网格 | 16×16 的整数倍 | 图集按 16px 对齐摆放 |
| 角色碰撞盒基准 | 见 1.2 | 视觉尺寸与碰撞盒分离 |

### 1.2 角色与实体尺寸（原创分级表）

| 类别 | 视觉尺寸（宽×高） | 说明 |
|---|---|---|
| 玩家（Player） | 24×40 | 约 1.5 格宽、2.5 格高，留有动画摆动余量 |
| 小型敌怪 | 16×16 | 一格体积单位 |
| 中型敌怪 | 32×32 | 两格体积单位 |
| 大型敌怪 | 48×48 | 三格体积单位 |
| 首领 | 96×128 ~ 128×160 | 以整数格放大，禁止非整数缩放 |

### 1.3 UI 与图标

| 用途 | 尺寸 | 说明 |
|---|---|---|
| 物品图标 | 16×16 | 统一等距，肩并肩摆放不溢出 |
| 快捷栏/背包格 | 32×32 | 含内边距的渲染格 |
| 交互按钮 | 32×32 / 64×64 | 常态 + 按下两态 |
| HUD 元素 | 16 的整数倍 | 对齐网格，禁止半格偏移 |

### 1.4 图集（Atlas / SpriteSheet）规则

1. 单张图集短边 ≤ 2048px，长宽须为 **2 的幂**
2. 帧与帧之间 **2px 间隙**，防邻帧边缘渗透
3. 同一实体的所有动画帧 → 同一图集；不同实体禁止混装一张图集
4. 图集内帧顺序固定为「行优先、从左到右、从上到下」

## 二、调色板规范

### 2.1 颜色上限

| 对象 | 单帧最大颜色数（含透明通道） |
|---|---|
| 单一物块/图标/小物件 | ≤ 8 色 |
| 角色/敌怪 | ≤ 16 色 |
| 首领 | ≤ 24 色 |
| 背景/大场景 | ≤ 32 色 |

> 限色目的是保证像素风格统一与可维护性，禁止渐变滥用（Photoshop 抗锯齿边缘除外，边缘过渡色计入上述上限）。

### 2.2 分层调色板（原创，禁对标作品标志色）

| 色板 | 主用途 | 基调方向 |
|---|---|---|
| 岩层环境板 | 地表/地下物块 | 暖灰土层 + 冷蓝靛地底，明度阶梯 4 档 |
| 生物板 | 玩家/友善 NPC | 中饱和暖色，避免高纯度荧光 |
| 敌怪板 | 敌怪 | 低明度高饱和，暗部主导 |
| 特效板 | 打击/爆炸/粒子 | 高亮橙金，短帧高对比 |
| UI 板 | 界面/图标 | 统一冷中性底 + 单强调色 |

**强制禁止项：**
1. 禁止成组、成比例照搬对标作品的标志性配色组合（如某作品的地表绿 / 腐化紫 / 雪地白的三元视觉签名）。
2. 禁止使用「像素零质感」的纯逻辑荧光色（#00FF00 类）作敌怪/角色主色。
3. 每个色板须附带原创色值表（RGB），入库时随资产一并登记。

### 2.3 全局公共色

| 色 | 用途 |
|---|---|
| 纯透明（alpha=0） | 所有精灵背景 |
| 纯黑 #000000 | 描边/剪影（可选） |
| 纯白 #FFFFFF | 高光 |

## 三、透明背景规范

1. 所有精灵以 **PNG** 保存，使用 **Alpha 通道**表达透明，禁止用纯色底（白/洋红）后处理抠图。
2. 精灵画布的背景像素必须 `alpha=0`，且与主体轮廓无「白色晕圈」「半透明残边」。
3. 单个文件只放一个精灵族（见命名 §6），禁止拼版式多角色塞进同文件却不提供图集坐标。
4. 半透明（0<alpha<255）仅允许用于：粒子淡入淡出、玻璃/冰面材质、投影软边；角色/物块主体边缘必须为 0 或 255（硬边像素风）。

## 四、动画帧规范

### 4.1 帧率（FPS）原创标准

| 动画 | 帧数 | 帧率 FPS | 循环 |
|---|---|---|---|
| 待机（Idle） | 2–4 | 4 | 循环 |
| 走 / 跑 | 6–8 | 8 | 循环 |
| 挖掘 / 挥击 | 4–6 | 10 | 单次（回待机） |
| 受击 | 2–3 | 12 | 单次 |
| 死亡 / 消失 | 6–8 | 10 | 单次（停在末帧） |

### 4.2 帧命名与排序

1. 单帧文件：`名称_序号.png`，序号从 `00` 起，两位补零（`_00`、`_01`…）。
2. 图集内帧序按 §1.4 第 4 条固定，动画播放顺序必须与帧序一致，禁止跳跃排列。
3. 左右朝向靠 **水平翻转** 复用，不额外产出一份镜像帧；仅当左右不对称（持械手）时才绘制双向帧并加 `_l`/`_r` 后缀。

## 五、音频格式规范

| 类型 | 格式 | 位深/采样 | 说明 |
|---|---|---|---|
| 背景音乐（BGM） | **OGG Vorbis**（.ogg） | 44.1kHz / 128–192kbps | 循环点须无缝拼接 |
| 环境音 | OGG Vorbis（.ogg） | 44.1kHz | 支持循环 |
| 音效（SFX） | **WAV**（.wav，短促）或 OGG | 44.1kHz / 16bit | 短于 2s 选 WAV，其余 OGG |

**强制禁止项：**
1. 禁止用带版权保护/来源不明的素材；全部音效须原创合成或自研音色库。
2. 禁止直接复用对标作品的音效波形与旋律主题（含改编）。
3. BGM 需登记：调式、拍号、时长、循环点时间戳。

## 六、命名规范（沿用目录结构规范 `类别_词根` 体系）

### 6.1 资产文件名类别前缀表

| 前缀 | 含义 | 示例 |
|---|---|---|
| `tile_` | 物块图块 | `tile_crystal_shell_00.png` |
| `char_` | 角色（敌我） | `char_guard_walk_00.png` |
| `obj_` | 环境物件/家具 | `obj_lantern_00.png` |
| `ui_` | 界面元素 | `ui_btn_confirm.png` |
| `ico_` | 物品图标 | `ico_ember_berry.png` |
| `fx_` | 特效/粒子 | `fx_hit_spark_00.png` |
| `bg_` | 背景图层 | `bg_cave_parallax.png` |
| `bgm_` | 背景音乐 | `bgm_layer_one.ogg` |
| `sfx_` | 音效 | `sfx_pickaxe_hit.wav` |

### 6.2 完整命名公式

```
资产文件名 = {类别前缀}_{词根}[_{变体}][_{帧序号或朝向}]".{png|ogg|wav}"
```

规则：
1. 全部 **snake_case 小写**，词根为原创英文或拼音词根，禁止出现对标作品词汇/谐音缩写（入库前过黑名单）。
2. `词根` 与 data 层 ID 词根保持一致（如物品 `item_crystal_shell` ↔ 图标 `ico_crystal_shell.png` ↔ 掉落地 `tile_crystal_shell_00.png`）。
3. 帧序号两位补零，朝向用 `_l`/`_r` 后缀。
4. 单文件不含帧序（静态图标/UI）；含帧序即属动画序列（§4.2）。

### 6.3 与 data / 代码 ID 的关系

| 层 | 标识 | 规则 |
|---|---|---|
| 数据物品 ID | `item_` 前缀 | 由 item.schema.json 冻结 |
| 可放置物块 ID | `tile_` 前缀 | 与 `tile_` 资产词根同源 |
| 美术资产文件 | §6.1 类别前缀 | 词根与 ID 词根对齐，前缀按资产类型区分 |
| 代码类/字段 | PascalCase / `_camelCase` | 见编码规范，不直接拼资产文件名 |

## 七、资产入库校验清单（逐条可勾选）

1. [ ] 尺寸符合 §1 分级，未做非整数缩放
2. [ ] 单帧颜色数 ≤ 该对象上限（§2.1）
3. [ ] 背景为纯透明 alpha，无白边/洋红底/半透明残边（§3）
4. [ ] 动画帧率与帧数符合 §4.1，帧序号两位补零
5. [ ] 音频格式/采样符合 §5，BGM 已登记循环点
6. [ ] 命名符合 `类别前缀_词根_变体_帧序` 公式，小写 snake_case
7. [ ] 词根通过黑名单扫描，无对标作品痕迹
8. [ ] 已附原创调色板色值表 + 资产入库单

> 任一未勾选，资产不得进入 assets/ 主干分支。
